# New Repository Checklist

Use this checklist when creating a new repository or onboarding an existing one.

## Foundation

- [ ] Repository follows naming conventions (`ael-` prefix, lowercase, hyphenated)
- [ ] Description set on GitHub
- [ ] Repository is public (unless there's a reason for private)
- [ ] Topics/tags set on GitHub

## Legal

- [ ] LICENSE file added matching the asset type (see LICENSE-POLICY.md)
- [ ] README license line matches LICENSE file
- [ ] Copyright line uses "AEL Digital Studio"
- [ ] GitHub License field matches LICENSE file

## Documentation

- [ ] README.md with clear purpose in first paragraph
- [ ] Quick Start / Getting Started section
- [ ] Learning Metadata section (for educational repos)
- [ ] Cross-links to related repos and catalog (for educational repos)
- [ ] CHANGELOG.md (for active projects)

## Configuration

- [ ] .gitignore configured for project type
- [ ] .nojekyll (for GitHub Pages static sites)
- [ ] CI/CD configured (GitHub Actions)

## Community

- [ ] CONTRIBUTING.md (for active projects)
- [ ] CODE_OF_CONDUCT.md
- [ ] SECURITY.md with contact email

## Branding

- [ ] ael-logo.svg at root
- [ ] AEL color palette used (`#0074FF` primary)
- [ ] README footer with "Built by AEL Digital Studio"
- [ ] GitHub Pages preview image (screenshot.svg)

## Lifecycle

- [ ] Status is clear (Active / Deprecated / Archived)
- [ ] If archived: redirect notice + GitHub archive setting
- [ ] If deprecated: deprecation notice in README

---

## Onboarding an Existing Repository

For repos that predate governance standards:

- [ ] Run the full checklist above
- [ ] Resolve any license contradictions (README vs LICENSE file)
- [ ] Standardize copyright to "AEL Digital Studio"
- [ ] Add any missing community files
- [ ] Update description and topics on GitHub
