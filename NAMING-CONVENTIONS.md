# Naming Conventions

## Repository Names

- **Prefix**: All AEL repositories use `ael-` prefix (e.g., `ael-engineering-academy`, `ael-omega-platform`).
- **Hyphenated**: Words are separated by hyphens, not underscores or spaces.
- **Lowercase**: All repository names are lowercase.
- **Descriptive**: The name describes the project's function (e.g., `ael-image-color-extractor`, not `ael-color-tool`).

Exceptions:
- Personal websites use the GitHub Pages format (`aymanelmasryael.github.io`, `aymanelmasry.me`).
- Third-party academic repos may use their original naming (`AEL-Sovereign-CS50x-2026-2027`).
- Legacy repositories retain their original names after archiving.

## File Naming

- Use lowercase with hyphens for project files (`ael_color_os.js` → legacy; prefer `ael-color-os.js` for new projects).
- README is always `README.md` (uppercase).
- License is always `LICENSE` (uppercase, no extension).
- Community files follow standard GitHub naming (`CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`).

## Branch Naming

- Feature branches: `sprint1/descriptive-name`
- Hotfix branches: `hotfix/description`
- No direct pushes to `main` or `master`.
